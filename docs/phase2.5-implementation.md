# フェーズ2.5：実装と起動手順

## 実装した機能

- 部屋作成時に起床日・時刻・金額を選択。初期値で勝手に確定しない。
- 起床時刻は04:00〜11:00、金額は100〜2000 WPの整数。日付は日本時間で解釈し、現在以前の起床日時を拒否。
- 作成前に日時と金額をまとめて表示。作成者自身もその条件で参加。
- コード入力で条件だけを確認し、「この条件で参加する」か「参加しない」を選択。
- 条件確認・辞退はDBに参加者を書き込まない。参加確定時に明示的同意と表示条件の一致を検証。
- 作成後の日時・金額の変更禁止をDBトリガーで保証。
- 重複参加・満員・受付終了・過去日時・旧部屋の条件未設定を処理。
- 全員が同意して参加したらreadyへ遷移。自動開始・アラーム用データの生成はフェーズ3の対象。

## 利用前に必要なDB作業

DB担当者が、フェーズ2の4テーブルと `supabase/phase2.sql` の適用済み環境で、**`supabase/phase2.5.sql` 全体**をSQL Editorで実行してください。
この作業では共有Supabaseへ移行SQLを適用していません。以前のフェーズ2用SQLだけでは、新しい部屋作成・条件確認・参加は動作しません。

旧作成・参加RPCの権限が無効になるため、DBと画面・APIを同じタイミングで切り替えてください。既存部屋・ユーザー・参加者は削除しません。旧部屋の未設定条件を勝手に補完したり、参加者を承認済みにしたりしません。
実施前のデータ確認、権限、戻し方は [DB引き継ぎ書](phase2.5-db-handoff.md) を参照してください。

## 起動

環境変数はこれまでの `.env.local` の2項目を継続利用します。追加の秘密鍵は不要です。

Windows PowerShellでnpmのスクリプトがブロックされる場合は、次のように `npm.cmd` を使います。

```powershell
npm.cmd run dev
```

本番ビルドの確認：

```powershell
npm.cmd run build
npm.cmd run start -- --port 3200
```

起動済みのサーバーは、ソースや環境変数の反映が必要なら再起動してください。今回の確認用プレビューはポート3200です。

## テストと確認結果

- Next.js本番ビルド・TypeScriptチェック成功。
- 既存のフェーズ2 SQLテスト7件。
- フェーズ2.5 SQLテスト11件：移行、旧データ保持、100／2000 WP・04:00／11:00、範囲外、無効日付、参加前の情報制限、同意・条件一致、ready、期限、変更禁止、権限、トランザクション、再適用。
- フェーズ2.5 入力検証テスト3件：日本時間、暦上存在しない日付、金額・時刻、過去日時、同意とタイムゾーンを含む条件の形式。
- Edge・390px幅・米国タイムゾーンでの画面確認：日本時間表示、入力範囲、確認と辞退の書き込みゼロ、参加確定、参加済み表示、readyの自動更新、再読み込み、満員・旧部屋・期限切れ、確認後に満員となるケース、コード変更時の古い応答の破棄。横にはみ出し・JavaScriptエラーなし。

PGliteテストのAuthは検証用の `auth.uid()` に置き換え、画面テストのAPI応答は明示的な仮データです。実際のSupabase Authと新API・新SQLをつないだ保存・参加、および複数接続による同時参加は未確認です。移行後に実接続で確認してください。

テスト用パッケージはアプリと分けて `tests/` に置いています。Node.js 24以上を使用します。

```powershell
cd tests
pnpm install --frozen-lockfile
node --test phase2-db.test.mjs phase25-db.test.mjs phase25-validation.test.mjs
# 別ターミナルで上記の本番サーバーを3200番で起動した後
node phase25-ui.mjs
```

`pnpm` がない場合、テスト用の依存だけを `tests/` 内で `npm.cmd install --package-lock=false` により用意できます。アプリ直下の依存をこの目的で変更する必要はありません。
画面テストは既定でインストール済みEdgeを使います。必要に応じて `TEST_BROWSER_CHANNEL=chrome`、`TEST_BASE_URL` を環境変数で指定してください。画像は `tests/artifacts/phase25/` に保存され、Gitには含めません。

## DB適用後の実接続確認

1. Aさんが2人部屋を作る。起床日・07:00・500 WPを指定し、Aさんが1人目として入ることを確認。
2. 別ブラウザのBさんがコードを入力し、同じ日付・時刻・金額を確認。ここでは人数が増えないことを確認。
3. 「参加しない」で戻っても人数が増えないことを確認。
4. 再検索して「この条件で参加する」を押すと2人になり、Aさんの画面もreadyを表示することを確認。
5. 再読み込みでも条件・参加が維持されることを確認。
6. 3人目は新規参加不可。同じ参加者の再送でも人数が増えないことを確認。
7. 旧部屋は閲覧できるが、条件未設定なら新規参加できないことを確認。
8. `wake_checks` はまだ作成されず、自動開始・アラームは実行されないことを確認。
