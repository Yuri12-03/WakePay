# 起床結果・WP分配デモ

## 利用開始

Supabase SQL Editorで `supabase/demo-results.sql` の全文を実行してください。最後は **COMMIT;** です。ROLLBACKにすると追加が取り消されます。既存のフェーズ3まで適用済みであることが前提です。この作業では共有DBへ適用していません。

実行に成功したら全員参加済みの部屋を開き、待機画面の「起きられましたか？」を使います。起床日時の前後に関係なく何度でもデモできます。

1. 各参加者が自分の端末で「起きられた」「起きられなかった」を選びます。
2. 全員が答えるまでは未回答人数と各自の回答を表示し、分配は未確定にします。
3. 全員回答後、同じ画面に成功・失敗とWPの増減を表示します。他端末にも約3秒で反映します。
4. 部屋作成者が「結果をリセットする」→「全員の結果をリセットする」を押すと、全員が再度選べます。途中でもリセットできます。

## 分配ルール

失敗者は設定額を失い、その合計を成功者へ均等分配します。端数は最初に成功を送信した人へまとめて加算します。サーバー記録の時刻が同じ場合はユーザーID順で決めます。
全員成功は全員0 WP、全員失敗は全員が設定額を失い分配なし。成功者の表示額は利益分であり、累計残高や預け入れ額ではありません。

例：3人、101 WP、2人成功・1人失敗なら、最初の成功者 +51 WP、次の成功者 +50 WP、失敗者 -101 WPです。

## DB・API

- 追加テーブル：`wp_demo_rounds`、`wp_demo_answers`。実際の `wake_checks` と部屋の状態は変更しません。
- `GET /api/rooms/[roomCode]/demo` → `wp_demo_room`（読み取り専用）。
- `POST /api/rooms/[roomCode]/demo`：`{ action: "answer", round: 1, success: true }` → `wp_demo_submit`。
- 同POST：`{ action: "reset", round: 1 }` → `wp_demo_reset`（作成者のみ）。
- Auth・参加者チェック、RLS、テーブル直接アクセス禁止。本人IDはauth.uid()で決め、クライアントから受け取りません。
- 回答・リセットは部屋行をロックして直列化します。同じ回答の再送は重複せず、回答の変更はリセットまで拒否します。
- リセットでroundを増やし、古い画面の回答・二重リセットを拒否します。リセットはデモ回答のみ削除し、実際の起床確認データを保持します。
- SQLは再実行可能です。既存のデモ回答を初期化しません。
